# CLAUDE.md

Read and follow @~/.config/agents/AGENTS.md.

File guide for Claude Code (claude.ai/code) for repo work. See `TIDE_INTEGRATION.md` for how tide's waveform db is wired in and which pieces are still mocked; `docs/sidecar.md` (+ `docs/sidecar.schema.json`) for the sidecar format; `docs/sdi.md` (+ `docs/sdi.schema.json`) for the **source debug info** format — the design-side counterpart to the sidecar (types, enums, source spans, dataflow for cone-of-influence). Its worked example is `samples/sdi/`, `tools/sdi-cone.mjs` is the reference consumer (elaborate, bind to a trace, driver/reader/cone queries), `crates/sdi` is the format's Rust definition (types, encodings, structural invariants, gzip), `crates/sdi-verilator` is the producer from `verilator --json-only`, and `tests/sdi.test.cjs` plus `cargo test -p sdi -p sdi-verilator` guard all of it. **The importer is `native/src/design.rs`**: it loads `<trace>.sdi.json[.gz]` (or `$RIPTIDE_SDI`) beside the trace, elaborates the design once, indexes it by trace path, and hands `hierarchy.rs` the declared types, directions, ranges, declaration sites, doc comments, enum tables and scope kinds that `getHierarchy` then emits per node. All optional: no SDI means the VCD-grade tree, which is what every trace but the bundled mock gets today. The bundled mock ships `native/src/mock.sv` + `native/src/mock.vcd.sdi.json` so the demo shows source integration without a simulator.

## Commands

Run from repo root. Six scripts, all driven by one cross-platform Node orchestrator (`scripts/build.mjs`) — no shell builtins, no per-platform script variants:

- `pnpm dev` — build the host-native addon + app (Debug) and launch Electron (`scripts/dev.mjs`). `pnpm dev --blank` boots the idle/no-trace UI (`RIPTIDE_NO_TRACE`).
- `pnpm build` — release build of everything into `dist/`: native addon (`cargo build --release`, copied to `dist/native/riptide.node`) + main process (`tsc`, CommonJS → `dist/main`) + renderer (`scripts/build-ui.mjs`, esbuild + Tailwind, minified) + `index.html`.
- `pnpm check` — all static checks (`scripts/check.mjs`): WGSL validation (`naga --bulk-validate`, skipped with a warning if `naga` absent) + both tsconfigs type-checked (`tsconfig.json` main, `tsconfig.renderer.json` renderer).
- `pnpm test` — `scripts/test.mjs`: builds the host addon, then runs `check` + the cargo oracle & headless node suites (`tests/run.sh`) + the Electron visual regression (`run-headless.sh`) + the GPU canvas golden (deno). Suites whose tool is missing (bash / sway / deno / a display) self-skip. `pnpm test --update` regenerates the visual + canvas goldens. See `TESTING.md`.
- `pnpm release` — `pnpm build` + electron-builder for the host platform (config in `electron-builder.yml`) → `dist/installers/`. `dist/native/**` is asar-unpacked.

**Auto-update** (`src/main/updater.ts`, contract in `src/shared/update.ts`, UI in the About card). electron-updater against GitHub Releases, but only some artifacts can self-update, and the split is forced by the tooling, not chosen: **Linux AppImage**, **Linux deb** and **Windows `nsis`** update in place; **Linux `tar.gz`** and **Windows `portable`** cannot (no installer to hand an update to — and electron-builder sets `isWriteUpdateInfo: false` for portable, whose exe does not implement the `/S`+`/D=` flags `NsisUpdater` drives installs with), and **macOS** cannot while builds are ad-hoc signed (`mac.identity: "-"`) because Squirrel.Mac pins the running bundle's *designated requirement*, and an ad-hoc DR is a bare `cdhash` bound to one exact binary — fixing it needs a Developer ID Application certificate, not a config change. Everything else falls back to a GitHub-API version check plus a link to the release. Policy: `autoDownload = false` (consent first), one silent check 5s after launch whose failures are logged and swallowed, and `autoInstallOnAppQuit = true` — **except deb**, whose install shells out to pkexec/sudo `dpkg -i`; a graphical password prompt raised while the app is tearing down is missed or hangs, so deb installs only on an explicit Restart Now (`UpdateStatus.ready.installOnQuit` carries this to the UI).

`updaterKind()` picks the updater class **explicitly** rather than using electron-updater's `autoUpdater` export, and that is load-bearing. That export's factory picks the Linux class by reading `resources/package-type`, which electron-builder's `FpmTarget` writes into the *shared* `linux-unpacked/resources` dir — the same staging directory the AppImage and tar.gz are packed from. Whether they inherit it is pure target-build-order luck, and if they ever do, the factory hands those users a `DebUpdater` that runs `sudo dpkg -i`. So: `APPIMAGE` env var is checked first (authoritative for AppImage), and deb requires *both* the marker file and `process.execPath` under `/opt/Riptide` (where the deb installs), so an unrecognised layout degrades to the manual path instead of running dpkg. The chosen mode is logged once per session as `[updater] mode=…` — it depends on env vars and a packaged file that are invisible from outside, so it is the first thing to check on any update bug.

The release must carry `latest.yml` (Windows) / `latest-linux.yml` next to the installers or the updater 404s — `release.yml` uploads them explicitly. `latest-mac.yml` is deliberately *not* uploaded: both mac runners emit one and they collide on the same asset name. Two related traps: electron-builder's GitHub publisher creates **drafts** by default and a draft is invisible to the updater (CI's manual-dispatch builds rely on this to stay unofferable), and GitHub's `/releases/latest` excludes pre-releases — so `release.yml` derives the `prerelease` flag from whether the version has a `-suffix` rather than hardcoding it, or the first stable release would silently stop being found.

**Renderer death** is handled in two places, and both exist because a dead renderer used to be *silent* — the window stayed up showing a blank page and the only symptom was an unrelated `webContents.send` failing. (1) `src/main/index.ts` handles `render-process-gone`: it logs `reason`/`exitCode` (the actual diagnostic — "oom" and "killed" mean very different things) and offers a Reload, deliberately a prompt rather than an automatic reload so a reproducible crash can't become an infinite loop. (2) **every** main→renderer message MUST go through `sendToWindow` (`src/main/send.ts`) — a crashed renderer keeps its `BrowserWindow`, so `win.isDestroyed()` is false while the render frame is gone, and `send()` in that state logs "Render frame was disposed before WebFrameMain could be accessed". Electron *catches* that internally, so a try/catch cannot suppress it; the guard that works is `webContents.isCrashed()`.

**GPU generations** (`src/renderer/wave/WaveCanvas.tsx`): `boot()` builds one complete generation (device, pipelines, rAF loop, 9 DOM listeners, 6 store subscriptions) and a device loss tears it down and boots a replacement. The invariant is that a generation may only register anything if it still owns `teardown`, because `cleanups` is populated at the very END of a multi-hundred-millisecond async init while the loss handler that abandons it can fire at any point during that window. Hence the `generation` counter and `stale()` — checked after **every** await. Without it, a loss landing mid-init leaves a fully-wired generation whose cleanups array is unreachable forever: its store subscriptions keep running on every state change, its listeners on every pointer move, and its `device.destroy()` never runs. The retry budget resets on each successful frame, so it recurs for the whole session — an hours-to-manifest leak that presents as an eventual renderer OOM. Any new `await` in `boot()` needs a `stale()` check after it.

**The build orchestrator** (`scripts/build.mjs`): `node scripts/build.mjs [--target=<host|linux-x64|windows-x64|macos-arm64|macos-x64>] [--mode=<dev|release>] [--steps=<all|native|app>]`. `host` builds the addon for the current machine — what the CI matrix does on each of its per-platform runners; the explicit triples ask cargo to cross-compile and need that Rust target plus a linker for it installed locally (unlike the Zig toolchain this replaced, cargo does not cross-compile for free). One mapping table turns each target's cargo output (`.so`/`.dylib`/`.dll`) into the single canonical addon name `riptide.node` (an installer is one platform, so no per-OS filenames), and copies the `query-fixture` binary the differential suite needs beside it. `napi-build` handles the platform link quirks: `-undefined dynamic_lookup` on macOS, and on Windows nothing at all — napi-sys resolves the Node-API entry points at module init through the running `electron.exe` image. The CI release workflow (`.github/workflows/release.yml`) calls this exact script on a per-runner matrix — no bash re-implementation of the build.

Requires a Rust toolchain (edition 2024, so ≥ 1.85) and the **tide** git submodule at repo root (`./tide`, path-depended on from `native/Cargo.toml` as `../tide/crates/tide-core` and `../tide/crates/tide-vcd`; `build.mjs` preflights it with a clear error — run `git submodule update --init` after cloning). tide carries its own cargo workspace, so the root `Cargo.toml` excludes it. The root workspace has three members: `native` (the addon) plus `crates/sdi` and `crates/sdi-verilator` (the SDI format and its producer) — `build.mjs` builds `--package riptide-native`, so the SDI crates never enter the app build. `naga` (`cargo install naga-cli`) is needed only for `check`/`test`'s WGSL pass. All are build-time only — testers running a packaged build need none. No linter; tests via `pnpm test`.

## Architecture

Single-package repo at root (`riptide`). Electron app rendering digital waveforms via WebGPU. Waveform data comes from a real VCD on disk, parsed by tide-vcd in a Rust napi addon.

**Main process** — `src/main/index.ts`. Enables `enable-unsafe-webgpu` (+ Vulkan on Linux), opens BrowserWindow. The trace path is carried to the renderer in the window URL (`?vcd=<abs path>`); defaults to the bundled `native/src/mock.vcd`. Loads `http://localhost:5173/?vcd=…` when `RIPTIDE_DEV` set, else `dist/renderer/index.html`. The `riptide:open-vcd` IPC handler shows a native file dialog and returns the chosen path — the renderer then swaps the trace **in place** (no window reload; see `swapTrace` below). `riptide:open-external` opens a URL in the user's browser (Help ▸ Documentation, the About card's source link) — **https only**, and never in a BrowserWindow: a remote page must not navigate this window away or get a renderer with nodeIntegration.

**Native addon** (`native/src/`, Rust + napi-rs → `dist/native/riptide.node`): `lib.rs` registers the napi surface — `loadVcd(path)`, `getMockSegments(specs, qStart, qEnd)`, `getHierarchy()`, `getValueAt(handle, tick)`, `getEdges(handle, start, count)` (up to `count` transitions at/after `start` — a cheap prefix read for clock period/phase + reset-band detection; see `wave/clock.ts`), `searchTree(query)` (the fuzzy name filter, **async** — resolves a promise off the JS thread) and `markStrings(candidates, query)` (the same matcher over a caller-supplied list, sync). `trace.rs` reads a VCD path through `tide_vcd::load` into a `tide_core::Trace`, plus the trace end and timescale from its `LoadReport`; `hierarchy.rs` flattens tide's scope tree into the dense node array the renderer walks, building `search.rs`'s path index in the same walk (so index entry `i` is node `i`). `search.rs` is the fuzzy matcher: one byte pool of every node's dot path (tide interns those already) plus a per-node character-presence mask that rejects most of a hierarchy with one AND. It **matches, it does not rank** — the tree shows its hits in tree order, so precision comes from the rule instead: whitespace splits a query into terms that must all match, an undotted term has to fit inside **one** path segment (else `pc` "matches" `TOP.pipe.decoder.rd`), a term spelling a `.` may span them, and within a segment a forward pass finds the earliest match and a backward pass tightens the offsets. `Flat::prune` then turns the matched ids into the pruned row list the tree renders (matches plus the scopes above them, in tree order, with depths). Match flags are AND over terms, highlight offsets are the union of the terms that *did* hit — so a row highlights the part of its own name the query touched even when another term matched an ancestor. `Loaded.hierarchy` is an `Arc`, so a background filter survives a trace swap. Both are cached (`loadVcd` swaps them, leaving the prior trace intact on a bad open). `pack.rs` `pack_signal()` turns a signal's tide transitions into a row-agnostic `PackedSignal` (segments with row bits 0, value samples, labels), and `segments.rs` owns the pooling/finalize (see Conventions). Errors are JS exceptions, never aborts: an unknown or unstorable handle packs to an empty row rather than killing the frame. Every buffer crossing to JS is copied into a V8-owned `ArrayBuffer` — Electron's memory cage rejects an external backing store, and `napi`'s own `ArrayBuffer::copy_from` is broken (allocates, never copies), so `lib.rs` calls `napi_create_arraybuffer` directly.

**Renderer** — `src/renderer/index.tsx` → `App.tsx`. **SolidJS** (JSX lowered by `babel-preset-solid` via the esbuild plugin `scripts/esbuild-solid.mjs`). App state is a **Zustand** store (`store/store.ts`) exposed to components through `solid-zustand` (`useAppStore()`, fine-grained reactive reads) and read synchronously by the rAF loop / native handlers via `useAppStore.getState()` / `.setState()` — no stale-closure problem, so there are no state/ref mirrors. The persisted document slice maps 1:1 onto the sidecar (`selectSidecarText` + `startAutosave`). Renderer styling is **Tailwind v4**, compiled by the esbuild plugin `scripts/esbuild-tailwind.mjs` from `src/renderer/index.css` → `dist/renderer/index.css` (linked from `index.html`); utilities use a `tw:` prefix and preflight is disabled (`@apply` hybrid for shared component rules). The **framework-agnostic** data/GPU layers (`gpu/`, `hier/`, `native.ts`, `perf.ts`, `runtime.ts`) are plain `.ts` sitting alongside the Solid components, all under `src/renderer/`:

- `runtime.ts` — reads `VCD_PATH` / `SIDECAR_PATH` from the window URL once at module load to bootstrap the first trace.
- `native.ts` — typed bridge to the addon; marshals `getHierarchy` raw nodes into the `Hierarchy` map, exposes `loadVcd`, `getMockSegments`, `getValueAt`, and the two search entry points: `searchTree` (async, returns the pruned row buffers `ids`/`depths`/`matched`) and `markStrings` (sync, per-candidate match flag + UTF-16 highlight ranges ready to slice a JS string with).
- `hier/` — trace/view model. `types.ts` (`Hierarchy`, `Scope`, `Signal`, …), `hierarchy.ts` (lookups), `scene.ts` (builds `SCENE` = hierarchy + active signal rows + pack specs; `INITIAL` = cursor/markers/time window), `sidecar.ts` (persistence). `SCENE`/`INITIAL`/`SIDECAR` are `let` exports — `swapTrace(path)` reassigns them (reload native db → reload sidecar → rebuild scene). On an in-app "Open VCD…", `App.handleOpenVcd` calls `swapTrace` then `store.resetForTrace()` (one atomic `setState` re-seeding the document slice from the new `SCENE`/`INITIAL` + bumping `traceNonce`); the canvas's `traceNonce` subscription resets the viewport, and the `activeSignals` subscriptions repack — no window reload.
- Components (all under `src/renderer/`): `App.tsx` (layout grid, panel collapse/resize, Open-VCD swap), `wave/WaveCanvas.tsx` (GPU init + the rAF render loop), `wave/viewport.ts` (pan/zoom/fit controller, transient render state outside the store), `ActiveSignals.tsx` + `ActiveSignal.tsx` (signal rows; per-row value cell is a `createMemo` on `cursorTicks`), `SignalTree.tsx` (virtualized + slide-animated hierarchy tree, keyed by node id; owns the filter box, and with a query renders the natively-pruned tree — matches in place with their scopes opened, chevrons hidden because every kept scope is already open, and `expandedScopes` untouched so the sidecar never sees a search; double-clicking a matched scope leaves the filter and opens that scope in the full tree), `highlight.tsx` (`Highlight` + `clipRanges`, shared by both search surfaces), `WavesToolbar.tsx`, `MarkersBar.tsx`, `EditableNum.tsx`, `ColorPicker.tsx`, `ClockPicker.tsx` (clock-format/timebase picker), `EnumDialog.tsx` (per-row enum-table editor), `AboutDialog.tsx`, `ShortcutsDialog.tsx` (Help ▸ Keyboard Shortcuts — its rows are read out of the live menu tree, so a shortcut cannot be listed in one and missing from the other), `ContextMenu.tsx`, `MenuBar.tsx`, `GlobalTooltip.tsx`, `HoverReadout.tsx`, `PerfOverlay.tsx`. Value/enum-label formatting in `wave/value.ts`, ruler/clock/time helpers in `wave/format.ts`, packed colors in `wave/palette.ts`, layout/zoom constants in `wave/constants.ts`. Canvas PNG snapshot (Save Canvas / Export) via `wave/capture.ts` (drained by the rAF loop right after `renderFrame`); the `window.__bench` pack-cost harness lives in `bench.ts`.

**WebGPU pipeline** (`src/renderer/gpu/`):

- `device.ts` — `initGPU(canvas)` sets up adapter/device/ctx (requests `timestamp-query` when available); `resizeCanvas` syncs the backing store with CSS size × DPR.
- `data.ts` — `Viewport` shape + viewport packing (`writeViewportInto`, `VIEWPORT_BYTES = 48`). The timeline end is the trace's last event time (native `end_t` → `SCENE.hierarchy.endTicks` → `TRACE_END`); the clock period/phase is the detected timebase grid (`store.clockGrid`, from `wave/clock.ts` `detectClockGrid` via native `getEdges`) — neither is a hardcoded constant.
- Native packing (`native/src/segments.rs`) — produces GPU-ready `PackedSegment` (3×u32: `t_start`, `t_end`, `row_flags`), `RowInfo` (7×u32 per row), and shared byte-stride sample pools `x0Pool` / `x1Pool` (value / unknown mask). Per-row `bytes_per_sample = ceil(bit_width / 8)` (= tide's `Type.bytes()`): each sample is that many consecutive bytes — tide's native per-sample byte run, so signals of any width are carried in full. `pack.rs set_samples` copies the whole `min` plane in one shot and derives the unknown mask with one XOR pass; there is no per-sample repack. The pools are bound as `array<u32>` (WGSL can't bind byte storage); the shader byte-addresses them, decoding `(lsb, msb)` per instance via `RowInfo.x0_offset` + `segment_start` + `bytes_per_sample`, OR-folding the sample's bytes (it only needs whole-sample non-zeroness to pick line/crosshatch/color). Each pool is padded to a 4-byte multiple (`finalize`) so `writeBuffer` accepts it. The CPU value path (`getValueAt`/`jsWordArray`) is independent and still returns u32 word arrays.
- `digital.ts` + `digital.wgsl` — one shader module; a `VARIANT` override constant (0 single, 1 multi) selects the variant at pipeline-build time. Vertex entry `vs_main`; fragment entries `fs_single` (1-bit waveform line) / `fs_multi` (multi-bit pill w/ rounded SDF). Triangle-strip rects, 4 verts × N instances. `buildPipelineFromPacked` compiles a variant async with its own segment storage buffer; `rebindPipeline` reuses an already-compiled pipeline with a fresh segment buffer (synchronous — so an active-signal add/remove repacks on the spot). Both variants share the per-scene `RowInfo` + sample pools from `createSceneBuffers`. 6 bind-group entries (uniform + 5 read-only-storage); alpha blending on. `wave/WaveCanvas.tsx` feeds `getMockSegments(buildPackSpecs())` from the addon — 1-bit rows go to the single buffer, wider rows to the multi buffer.
- `lines.ts`/`lines.wgsl`, `rect.ts`/`rect.wgsl`, `text.ts`/`text.wgsl` — the other instanced batch renderers (grid/cursor/marker lines, notch/pill rects, glyph atlas text). `colors.ts` — per-row color storage buffer (`MAX_ROWS`). `timing.ts` — `GpuTimer` (WebGPU `timestamp-query`, n/a fallback).
- `frame.ts` — `renderFrame` writes the viewport uniform once, then one render pass with clear: `linesBg`, `rectsBg`, each digital pipeline, `textBody`, `linesFg`, then per-pill `rect`+`text` overlays (each pill's own pair so its rect occludes earlier pills — painter's algorithm, no z buffer). Optional `GpuTimer`.

`wave/WaveCanvas.tsx` runs `requestAnimationFrame` (in `onMount`, after GPU init). Canvas size (`clientWidth`/`clientHeight`) is read live each frame; row height is `ROW_HEIGHT_CSS` (`wave/constants.ts`, mirrors the `--row-h` CSS var so canvas rows line up with the DOM `.s-row`s). `resizeCanvas` syncs the backing store on `ResizeObserver`; DPR-only changes (drag between displays) tracked via `matchMedia('(resolution: …dppx)')`, re-armed each fire. The active-signal value column is computed CPU-side via `valueAtTick` (native `getValueAt`) + `formatSegmentValue` (`wave/value.ts`, same LSB/MSB word convention as the shader).

**Perf overlay** (`perf.ts`, `gpu/timing.ts`, `PerfOverlay.tsx`): `perf.ts` lives at `src/renderer/` (not `gpu/`). Toggle the HUD with the backtick **`` ` ``** key, `?perf=1` in the URL, or `window.__perf.enable()`; `window.__perf.dump()`/`.snapshot()`/`.reset()` from DevTools. Tracks electron (main-thread rAF) present fps + dropped frames + longtask jank, canvas GPU pass ms (via `frame.ts`'s optional `GpuTimer`; n/a when unsupported), CPU encode ms, the trace-load phase breakdown (`stamp()`s finalized on first frame), VCD-swap phases (`swapMark`s in `swapTrace`), and add-signal latency (click → repack → present). Enable state persists in `sessionStorage`; frame metering + load stamps are always-on (cheap), GPU queries + overlay only when enabled.

## Conventions

- **Split tsconfigs**: `tsconfig.json` main = CommonJS to `dist`; `tsconfig.renderer.json` = the renderer (SolidJS app + shared `.ts`), `jsx:preserve` + `jsxImportSource:solid-js`. ESNext + Bundler resolution, no emit.
- **WGSL as text import**: esbuild `--loader:.wgsl=text`; types in `gpu/wgsl.d.ts`.
- **CPU/GPU layout must stay in sync** across Rust + WGSL: `PackedSegment` = 3×u32 (`t_start`, `t_end`, `row_flags`); `RowInfo` = 7×u32 (`x0_offset`, `x1_offset`, `bytes_per_sample`, `segment_start`, `flags`, `y_offset`, `height`) — offsets are BYTE offsets into the (u32-typed) pools, `bytes_per_sample = ceil(bit_width/8)`. The same struct is also declared (read-only, `flags` only) in `labels.wgsl`, so keep all three (`segments.rs`, `digital.wgsl`, `labels.wgsl`) in sync. `RowInfo.flags` bit 0 = row dim (eye toggle), bit 1 = highlight (selection), bit 2 = draw this row's value labels from the small glyph atlas (`labels.ts` `retier`, read only by `labels.wgsl`); native emits 0 and the renderer sets them directly via `setRowFlags` (a tiny `writeBuffer`, no repack — so it scales past 32 rows, unlike the old viewport bitmask). Viewport = 12 × 4 B = 48 B (16-aligned): `ticks_per_pixel:f32`, `start_ticks_int:i32`, `start_ticks_frac:f32`, `width:f32`, `height:f32`, `row_height:f32`, `dpr:f32`, `selected_row:i32`, `wave_y_offset:f32`, then 3×f32 pad (slots 9–11; row dimming moved to `RowInfo.flags`). `start_ticks` is split int/frac so shader subtraction (`f32(i32(t_start) - start_ticks_int) - start_ticks_frac`) keeps full integer precision for tick values > 2^24. Touch one side = update the other (`native/src/segments.rs`, `digital.wgsl`, `writeViewportInto` in `gpu/data.ts`).
- **Segment rowFlags packing**: `[15:0]` row index, `[16]` shade, `[17]` right edge, `[18]` rising edge, `[19]` falling edge, `[20]` mute. Logic values: tide stores a sample as **bounds plus a high impedance mask** (`min`, `max`, `z`) — a bit is unknown exactly where the bounds disagree, `x` is `(0,1)` and `z` is `(0,1)` with its `z` bit set. The two GPU pools carry `min` (the value, unknowns read as 0) and `min ^ max` (the unknown mask), which is all the shader needs: it OR-reduces each to whole-sample non-zeroness and picks a line level or a crosshatch, so x and z render alike. Telling them apart needs the third plane and happens CPU-side — `label.rs` and `wave/value.ts` are the two places that do it, and must agree byte for byte. Shader bits 16..23 of `row_flags` repack into `VertexData.flags[0..7]`; higher `VertexData.flags` bits come from per-sample decoded LSB/MSB and differ between the single and multi variants.
- **CSS-pixel + DPR contract**: all viewport dims (`width`, `height`, `row_height`, `ticks_per_pixel`) and all vertex/geometry coords fed to shaders are CSS px. Shaders divide by `viewport.width`/`height` (CSS) to get clip space; since the framebuffer is `clientSize × dpr`, the clip→framebuffer step *already* scales by DPR. Therefore **shader size literals (line/border thickness, gaps, corner radius, hatch spacing) are bare CSS px and must NOT be multiplied by `viewport.dpr`** — doing so double-applies DPR (a "1px" stroke becomes `dpr²` device px) and breaks cross-display consistency. The `dpr` uniform is retained for layout but currently unused by shaders. DPR is applied in exactly one place: `resizeCanvas` (`device.ts`) sizing the backing store. Text crispness is handled by rendering the glyph atlas at `2×dpr` resolution (`text.ts`), not by scaling cell geometry.
- **Vertical-line alignment contract**: the ruler is the source of truth for where a line lands. `xForTick(t) = (t - startTicks) / ticksPerPixel` maps a logical time instant to its CSS-px x. `LINE_THICKNESS_CSS` (`wave/constants.ts`, = `thickness` in `lines.wgsl` — keep in sync) is how far a line extends.
  - **Time-aligned lines** (ruler notches, dashed grid, cursor, markers) are **left-aligned** to their logical time: the line's *left edge* sits on `xForTick(t)` and it extends `THICKNESS` px to the right. `lines.wgsl` left-aligns (`x_px + corner_x * thickness`), so CPU code passes `l.x = xForTick(t)` directly (no half-thickness inset). Notch rects use the same `r.x = xForTick(t)`, `w = LINE_THICKNESS_CSS`.
  - **Segment edges** (multi-bit gap; single-bit right edge / rising-falling caret) are **right-justified** to the segment, drawn *leading up to* the next segment's boundary `xForTick(t_end)`. The segment body is left-aligned to `xForTick(t_start)`, so each segment is itself left-aligned to its logical time. Segments are NOT centered (gaps/edges never straddle the boundary). This is already how `digital.wgsl` packs `pixel_bounds` (`-xgap_px` on the right; `edge_left_x = half - thickness`; caret apex biased `- thickness*0.5`) — no change needed there.
  - Consequence: segment edges deliberately do **not** line up with grid lines — a grid line's left edge starts on the boundary going right, while the segment edge ends on the same boundary coming from the left.
  - **Hover guide** is the one exception: it is **centered** on the pointer. It's still drawn with the left-align shader, but `updateHover` biases its tick left by `LINE_HALF_CSS` px so the left-aligned line renders centered on the pointer pixel. The reported logical time is thus ~½-thickness off the raw pointer pixel. `tickAtClientX` applies the **same** bias, so click-to-place cursor/markers land exactly where the centered hover line sat. Pill anchoring (`addFlag`), marker grab-test center, and span-arrow endpoints all account for the left-edge convention (add `LINE_HALF_CSS` to reach the visual center).
- **Trace vs. SDI vs. sidecar** — three sources, strict precedence. Hierarchy + waveform samples + enum integer *values* are **trace** data (the VCD, via tide). The **SDI** (`<trace>.sdi.json`, `native/src/design.rs`) is *design* data the trace cannot carry: declared types, enum label tables, directions, source spans, and `hints` — the producer's suggestions. The **sidecar** (`<trace>.sidecar.json`) is the *user's* view: which signals are active, their order/color/radix/role, cursor/markers/time window, UI chrome. Signals are keyed by hierarchical **path** (not run-specific handles or row indices), so a sidecar opens against any run of the same design whose paths still resolve.
  - **Precedence is sidecar > SDI hint > nothing.** `hints.role` arrives on the signal node as `hintRole` and seeds a row's role — in `makeActiveRef` (added from the tree) and as the fallback in `resolveView` (listed in a sidecar with no explicit role). An explicit sidecar role always wins: hints are the tool's opinion, the sidecar is the user's decision. Nothing infers a role from a signal's *name*.
  - Why it matters: "Align Grid to Clock" needs a row with `role: "clock"`, and on a trace with no hand-written sidecar the SDI is the only thing that can supply one. When that plumbing was missing the control sat permanently disabled on every real trace. Guarded at three levels — `native/src/design.rs` unit tests (hint parsing), `tests/clock.test.cjs` (the hint crossing into the JS hierarchy), and `tests/e2e/app.test.cjs` (the user-visible toggle, asserted on the marker pill switching to `#<cycle>`, which only happens when the detected grid is actually valid).
- **Time unit**: ticks = nanoseconds (integer). The bundled mock's clock has a 10 ns period / first edge at tick 5 (detected, not hardcoded) and runs to tick 90 (its last event time, surfaced as `endTicks`).
